# Онлайн-выставки — дизайн

## Обзор

Сейчас «выставка» на сайте существует только как анонс офлайн-события в
журнале (`posts` с рубрикой `exhibition`). Нужна **онлайн-выставка**:
кураторская подборка работ из каталога, которую можно «пройти» на сайте
и из которой можно купить работы.

Решения, принятые с владельцем проекта:

- **Назначение:** кураторские подборки из каталога, чтобы показать и
  продать работы. Не цифровая копия офлайн-выставок и не персональные
  выставки, которые собирают сами художники.
- **Время жизни:** у выставки есть даты «с … по …». После окончания она
  уходит в архив «Прошедшие выставки» и остаётся доступной.
- **Структура:** выставка делится на **залы** (1–5), у каждого название,
  вводный текст и упорядоченные работы.
- **Вид зала:** **стена в масштабе**: работы висят в реальном соотношении
  размеров (по сантиметрам), под каждой музейная этикетка; на десктопе
  горизонтальная лента, на телефоне вертикально по одной.
- **Кто собирает:** только админ, как и журнал. Отдельной роли куратора нет.

## Данные

Три новые таблицы в `src/db/schema.ts`, применяются через `npm run db:push`.

### `exhibitions`

| Поле | Тип | Примечание |
|---|---|---|
| `id` | uuid PK | |
| `slug` | text, unique, not null | генерируется из названия, как у постов |
| `title` | text, not null | |
| `subtitle` | text | одна строка под названием |
| `curator_name` | text | «Куратор: …» |
| `intro` | text | Markdown, кураторский текст |
| `cover_url` | text, not null | бакет `posts` (переиспользуем) |
| `starts_on` | date, not null | дата Душанбе |
| `ends_on` | date, not null | `ends_on >= starts_on` |
| `status` | text enum `draft`/`published`, default `draft` | |
| `post_id` | uuid → `posts.id`, on delete set null | необязательный анонс в журнале |
| `created_at`, `updated_at` | timestamptz | |

Индекс: `(status, starts_on)`.

### `exhibition_halls`

| Поле | Тип | Примечание |
|---|---|---|
| `id` | uuid PK | |
| `exhibition_id` | uuid → `exhibitions.id`, on delete cascade | |
| `position` | integer, not null | порядок залов |
| `title` | text, not null | «Горы» (номер «Зал 1» выводится по порядку) |
| `intro` | text | Markdown |
| `wall_color` | text | необязательный цвет стены из короткого списка пресетов |

### `exhibition_works`

| Поле | Тип | Примечание |
|---|---|---|
| `hall_id` | uuid → `exhibition_halls.id`, on delete cascade | |
| `artwork_id` | uuid → `artworks.id`, on delete cascade | |
| `exhibition_id` | uuid → `exhibitions.id`, on delete cascade | денормализовано ради уникальности |
| `position` | integer, not null | порядок работ в зале |
| `curator_note` | text | одна-две строки к работе |

PK `(hall_id, artwork_id)`; unique `(exhibition_id, artwork_id)`: одна
работа один раз на выставку. Индекс по `artwork_id` для плашки в карточке
работы.

Таблицы с RLS без политик, как `staff_accounts`: приложение ходит в БД
владельцем, публичный Data API Supabase их не видит.

## Правила видимости

Расчёт статуса — чистая функция в `src/lib/exhibitions/status.ts`:

```
exhibitionPhase(e, today) →
  'draft'    если status = draft
  'upcoming' если today < starts_on
  'open'     если starts_on <= today <= ends_on
  'closed'   если today > ends_on
```

`today` — это `todayInDushanbe()` из `src/lib/journal/post-form.ts`
(лучше вынести в общий модуль дат, если ему там тесно).

- Публично видны выставки в фазах `upcoming`, `open`, `closed`.
- `upcoming`: видна в списке (обложка, название, «Откроется 1 ноября»),
  страница выставки отвечает 404, пока выставка не открылась.
- `open`/`closed`: страница доступна; у `closed` сверху плашка
  «Выставка завершилась 30 ноября».
- Внутри показываются только работы со статусом `published` или `sold`.
  Остальные (снятые с публикации, на модерации) молча пропускаются.
- Зал без видимых работ не показывается. Если не видно ни одной работы,
  вместо залов выводится «Экспозиция обновляется».
- Проданная работа остаётся на стене с пометкой «Продано».

## Админка — `/admin/exhibitions`

Устроена по образцу `/admin/journal` (server actions, тот же доступ).

- **Список:** обложка, название, даты, метка фазы: «черновик», «скоро»,
  «идёт», «закрыта».
- **Форма выставки** (`/admin/exhibitions/new`, `/admin/exhibitions/[id]`):
  поля из таблицы, обложка через существующий загрузчик
  (`src/lib/uploads/upload-image.ts`, `crop-cover.ts`), выбор поста-анонса
  из списка постов рубрики `exhibition`. Валидация: обязательные поля,
  `ends_on >= starts_on`, уникальный `slug` (ошибка `slug_taken`, как у
  постов).
- **Залы** (на странице выставки): добавить, переименовать, удалить зал;
  переставить залы кнопками ↑/↓; поле вводного текста; цвет стены.
  Не больше 5 залов: на пятом кнопка «Добавить зал» пропадает, и сервер
  тоже не создаёт шестой.
- **Работы в зале:** поиск по каталогу (название или имя художника,
  только `published`/`sold`), «Добавить», кнопки ↑/↓, «Убрать», поле
  заметки куратора. Если работа уже стала невидимой, рядом пометка
  «Скрыта: не опубликована».
- **Публикация:** кнопки «Опубликовать» / «Снять с публикации»,
  «Предпросмотр» открывает публичный вид черновика (доступен только
  админу).
- **Удаление** выставки удаляет залы и связи (cascade), работы каталога
  не трогает.
- После каждого сохранения вызывается `revalidateTag('exhibitions')`.

## Публичные страницы

### `/exhibitions`: список

Три блока, пустые не выводятся:

1. **«Сейчас идёт»:** крупные обложки открытых выставок, «до 30 ноября».
2. **«Скоро»:** обложка и «Откроется 1 ноября», без ссылки внутрь.
3. **«Прошедшие»:** сетка поменьше, новые сверху.

Пункт «Выставки» добавляется в бургер-меню
(`src/components/sanat/burger-menu.tsx`) и в подвал.

### `/exhibitions/[slug]`: выставка

1. **Вход:** обложка на весь экран, название, подзаголовок, даты, куратор,
   кнопка «Войти в выставку ↓».
2. **Вступление:** кураторский текст (Markdown через существующий
   `markdown-body.tsx`).
3. **Залы** по порядку: «Зал 1. Горы», вводный текст, затем стена.
4. **Финал:** «Художники выставки» (аватар и ссылка на
   `/gallery/artist/...`) и «Другие выставки».

### Стена

Компонент `ExhibitionWall` (клиентский, только ради стрелок и просмотра).

**Масштаб.** Чистая функция `src/lib/exhibitions/wall-scale.ts`: на вход
размеры работ зала в см, на выход высота каждой работы в пикселях
относительно высоты стены. Самая высокая работа зала занимает
`WALL_MAX` (на десктопе около 60vh), остальные пропорционально её высоте
в см. Нижняя граница `WALL_MIN`, чтобы миниатюра 15×20 рядом с холстом
200×150 оставалась различимой. Работы выровнены по общей центральной
линии, как в экспозиции.

**Десктоп:** горизонтальная лента с `scroll-snap`, прокрутка колесом,
свайпом, клавишами ← → и кнопками-стрелками по краям.

**Телефон** (< 768px): работы идут вертикально, по одной; ширина
ограничена экраном, а масштаб между работами сохраняется в пределах
этой ширины.

**Этикетка** под работой: название, художник, год, техника, размер в см,
цена или «Продано», заметка куратора (если есть).

**Фото:** `next/image` с `width_px/height_px`, если они есть; для
масштаба нужны только сантиметры (обязательные поля), так что старые
работы без пиксельных размеров тоже встают правильно.

### Просмотр работы

Клик по работе открывает просмотр поверх страницы: большое фото,
этикетка, лайк (существующий компонент), кнопки «Подробнее / Купить»
(переход на `/gallery/artwork/[id]`) и «← Предыдущая / Следующая →»
(через все залы). Адрес меняется на `?work=<artworkId>`, так что ссылку
на конкретную работу на выставке можно отправить; Esc и «назад» в
браузере закрывают просмотр. Фокус удерживается внутри просмотра.

### Связи с остальным сайтом

- **Главная:** блок «Сейчас на выставке» (одна открытая выставка, самая
  свежая по `starts_on`), только если такая есть.
- **Пост журнала:** если на пост ссылается выставка (`post_id`), на его
  странице кнопка «Смотреть онлайн-выставку».
- **Карточка работы:** плашка «Участвует в выставке «…»» со ссылкой, если
  работа есть в открытой выставке.
- **SEO:** `generateMetadata` с обложкой как OG-картинкой; открытые и
  прошедшие выставки попадают в `app/sitemap.ts`.

### Кеширование

Страницы `/exhibitions` и `/exhibitions/[slug]` отдаются с ISR
(`revalidate: 60`, тег `exhibitions`), как журнал на главной. Функции
остаются в регионе `fra1`. 3D-библиотек нет; стена держится на CSS
(scroll-snap) и небольшом клиентском JS.

## Тестирование

**Unit (Vitest):**
- `exhibitionPhase`: границы дат (день открытия и день закрытия
  включительно), черновик.
- `wallScale`: пропорции, верхняя и нижняя граница, один элемент,
  одинаковые размеры.
- Форма: обязательные поля, `ends_on < starts_on`, генерация `slug`.

**Integration** (БД, `tests/integration`):
- Публичные запросы не отдают черновики, будущие выставки (страница)
  и работы со статусом не `published`/`sold`.
- Порядок залов и работ сохраняется и меняется перестановкой.
- Одна работа не добавляется дважды в одну выставку.
- `listReferencedImageUrls` включает обложки выставок.

**E2E (Playwright):**
- Админ создаёт выставку, добавляет 2 зала и работы, публикует;
  посетитель видит её в `/exhibitions`, открывает, листает стену,
  открывает работу в просмотре и переходит в карточку.
- Закрытая выставка показывает плашку и остаётся доступной.
- Выставка «скоро» видна в списке, а её страница отвечает 404.

## Порядок работ

1. Схема БД и чистые функции (`status`, `wall-scale`, форма) с тестами.
2. Запросы и админка.
3. Публичная страница со стеной и просмотром.
4. Связи: главная, журнал, карточка работы, меню, sitemap, references.
5. E2E.

## Не входит в первую версию

- 3D-зал от первого лица.
- Drag-and-drop в редакторе (пока ↑/↓).
- Выставки, которые собирают сами художники.
- Аудиогид, видео, комментарии посетителей.
- Отдельная статистика по выставке (пока Vercel Analytics по URL).
- Telegram-рассылка «открылась новая выставка» (бот уже есть, это
  естественный следующий шаг).
